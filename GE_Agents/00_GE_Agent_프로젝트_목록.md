## 공통 설계

- GE: 사용자 질문 해석, 도구 호출, 요약과 답변 제공.
- 기본 커넥터: Slack 등 공식 지원 데이터 연결에 우선 사용.
- 공통 연동 서버: 기본 커넥터로 부족한 Slack 수집, 외부 자료 수집, Microsoft Graph, 열차 API 연결. Cloud Run 등을 후보로 검토.
- 검색 저장소: 신기술 자료와 원노트 데이터를 각각 구분하여 저장·색인.
- 정기 실행: GE Workflow Builder의 일정 트리거 우선 검토. 실행 제약이 있으면 별도 스케줄러와 배치 작업 사용.
- 실행 기록: 성공·실패, 수집 범위, 중복 실행 여부, 마지막 동기화 시각 기록.

## MCP·RAG·Vector Search의 역할

| 항목 | 역할 | 적용 |
| --- | --- | --- |
| API / MCP | 외부 데이터와 기능 호출 | 네 프로젝트의 연동 |
| RAG | 검색한 자료를 근거로 답변 생성 | 신기술 자료·원노트 |
| Vector Search | 의미가 유사한 자료 검색 | 검색 품질에 따라 도입 |

별도 Vector DB는 초기 필수 조건이 아니다. 관리형 검색부터 시작하고, 정확한 제품명·날짜를 찾는 키워드 검색과 의미 검색을 함께 평가한다. MCP 자체가 자료 보관이나 검색 색인을 대신하지는 않는다.

## 권장 구축 순서

1. Slack 한 채널과 한 주 데이터를 이용하여 주간 보고 검증.
2. 신기술 자료 수집과 누적 검색 구축.
3. 원노트 한 섹션 연결 후 전체 범위로 확대.
4. 열차 조회를 연결하고 예약 연동 가능 범위 확인.

## 공통 확인 사항

- [ ] GE 앱에서 Workflow Builder·커넥터·커스텀 도구 사용 가능 여부 확인

- [ ] 실패 재시도와 중복 발송·중복 예약 방지 방식 결정
- [ ] GE 좌석 계약 범위와 별도 클라우드·API 사용 비용 확인
