# GE Agent 프로젝트 목록

Gemini Enterprise(GE)에서 사용할 일곱 가지 에이전트의 구축 기획이다. 주간 보고 프로젝트는 기능 POC를 완료했으며, 운영 전 비용·정책 확인이 남아 있다. 나머지 프로젝트는 요구사항과 권장 설계를 정리한다. 하루재 Agent는 번역·윤문·감수·교정 워크플로의 POC 진행 이력과 설정 자료를 정리했으며, 시험별 실제 결과 기록을 보완해야 한다. 연구개발 기획 Agent는 공고 통합 모니터링부터 시작해 연구자산 기반 후속 R&D 제안으로 확장하는 기획 단계다. EmoAI Agent는 콘텐츠 시청 반응 분석을 우선 대상으로 하며, 기존 분석 결과를 활용한 요약·질의응답부터 검증하는 기획 단계다.

## 공통 설계

- GE: 사용자 질문 해석, 도구 호출, 요약과 답변 제공.
- 기본 커넥터: Slack 등 공식 지원 데이터 연결에 우선 사용.
- 추가 연동: 기본 커넥터로 부족한 외부 연동은 기존 승인 서비스로 가능한지 먼저 확인한다. GWS/GCP 리소스나 별도 유료 서비스에 의존하는 설계는 제외한다.
- 검색 저장소: 신기술 자료와 원노트 데이터를 각각 구분하여 저장·색인.
- 정기 실행: GE Workflow Builder의 일정 트리거를 우선 검토하되, 예약 실행과 승인 없는 외부 전송을 구분한다. 별도 스케줄러는 GCP 금지 조건상 사용하지 않는다.
- 실행 기록: 성공·실패, 수집 범위, 중복 실행 여부, 마지막 동기화 시각 기록.

## MCP·RAG·Vector Search의 역할

| 항목 | 역할 | 적용 |
| --- | --- | --- |
| API / MCP | 외부 데이터와 기능 호출 | 연동이 필요한 프로젝트에 적용 검토 |
| RAG | 검색한 자료를 근거로 답변 생성 | 신기술 자료·원노트 |
| Vector Search | 의미가 유사한 자료 검색 | 검색 품질에 따라 도입 |

별도 Vector DB는 초기 필수 조건이 아니다. 관리형 검색부터 시작하고, 정확한 제품명·날짜를 찾는 키워드 검색과 의미 검색을 함께 평가한다. MCP 자체가 자료 보관이나 검색 색인을 대신하지는 않는다.

## 권장 구축 순서

1. Slack 한 채널과 한 주 데이터를 이용하여 주간 보고 검증.
2. 신기술 자료 수집과 누적 검색 구축.
3. 원노트 한 섹션 연결 후 전체 범위로 확대.
4. 열차 조회를 연결하고 예약 연동 가능 범위 확인.
5. 연구개발 공고 통합 모니터링을 검증하고 연구자산 기반 후속 R&D 기획으로 확장.

## 공통 확인 사항

- [ ] GE 앱에서 Workflow Builder·커넥터·커스텀 도구 사용 가능 여부 확인
- [ ] 주간 보고의 Slack 대상 채널·사용자와 승인 담당자 결정
- [ ] 사용자별 원본 접근 권한을 검색 결과에도 반영
- [ ] 인증 정보는 별도 보관하고 프롬프트·로그에 기록하지 않기
- [ ] 실패 재시도와 중복 전송·중복 예약 방지 방식 결정
- [ ] GE 앱 구독에 포함된 기능과 기존 서비스 연동 범위·추가 비용 확인 (GWS/GCP 사용 금지)
