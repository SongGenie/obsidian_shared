# 기차 조회 및 예약

상위 문서: [[GE_Agents/00_GE_Agent_프로젝트_목록]]

## 목표

서울역 ↔ 대전역, 서울역 ↔ 신탄진역의 열차를 자연어로 조회한다. KTX·무궁화 등 실제 운행하는 열차를 비교하고, 연동 가능한 경우 예약까지 지원한다.

> [!important] 예약 기능의 범위
> 시간표 조회는 TAGO 공공 API를 후보로 구현한다. 확인 기준일인 2026-10-15 현재 조사한 공개 문서에서는 일반 개발자가 바로 이용할 수 있는 코레일 좌석 예약·결제 API의 제공 여부와 사용 자격을 확인하지 못했다. 따라서 공식 예매 화면 연결은 기본 범위로, 에이전트 직접 예약은 공식·제휴 연동 수단 확보 후 구현하는 조건부 범위로 둔다. 공개 API가 없다고 단정하는 것은 아니다.

## 기능과 구현 단계

| 단계 | 기능 | 구현 조건 |
| --- | --- | --- |
| 1 | 운행시간표·열차 종류·소요시간 조회 | TAGO 응답 범위와 데이터 정확성 검증 |
| 1 | 공식 예매 사이트로 이동 | 검증된 공식 URL 사용 |
| 2 | 잔여 좌석·예약 가능 여부 조회 | 이를 제공하는 공식·제휴 연동 확보 |
| 2 | 선택 열차 예약 및 예약 결과 조회 | 예약 권한·사용자 인증·거래 상태 확인 수단 확보 |
| 3 | 결제·발권 지원 | 결제 수단과 지원 범위 확인 후 도입 |
| 3 | 예약 변경·취소 지원 | 규정·수수료·지원 API 확인 후 도입 |

공식 화면 연결에서 출발역·날짜 등이 자동 입력되는지는 지원 여부를 검증한다. 검증되지 않은 딥링크나 예약 URL을 만들어 제공하지 않는다. 직접 예약이 불가능하면 사용자가 공식 화면에서 예약을 완료하도록 안내한다.

## 조회 입력과 출력

입력: 출발역, 도착역, 탑승 날짜, 출발 또는 도착 시간대, 열차 종류, 인원, 좌석 등급, 편도·왕복 여부.

출력: 운행일, 열차 종류·번호, 출발·도착역, 출발·도착 시각, 소요시간, 제공되는 경우 운임, 좌석 상태와 조회 시각, 공식 예매 링크.

- “내일”, “이번 금요일”은 Asia/Seoul 기준 실제 날짜로 변환하여 표시한다.
- 역명은 API 역 코드 목록으로 확인한다.
- 신탄진에 특정 열차 종류가 정차한다고 가정하지 않는다.
- 직통편이 없으면 없다고 알린 뒤 환승 검색은 별도 선택 기능으로 제공한다.
- 좌석 상태를 조회하지 못하면 “확인 불가”로 표시한다. 시간표가 있다는 이유로 “예약 가능”이라고 답하지 않는다.
- 왕복은 각 방향을 따로 조회하고 한쪽만 성공한 경우를 구분한다.

## 조회 흐름

1. 자연어 요청에서 날짜·역·시간대·인원 등을 추출한다.
2. 필수 조건이 없으면 사용자에게 확인한다.
3. 열차정보 API를 호출하고 페이지 전체를 확인한다.
4. 조건에 맞게 필터링·정렬하고 조회 시각과 함께 표시한다.
5. 사용자가 선택한 열차에 대해 공식 예매 화면 또는 지원되는 예약 단계로 연결한다.

## 조건부 예약 흐름

1. 예약 도구의 지원 여부와 사용자 인증 상태 확인.
2. 선택 열차의 좌석 상태와 운임 재조회.
3. 날짜·구간·시간·인원·좌석 등급·금액을 제시하고 예약 의사 확인.
4. 중복 요청 방지 키를 부여하여 예약 요청.
5. API 응답과 예약 내역을 조회하여 실제 성공 여부 확인.
6. 예약번호, 결제 기한, 현재 상태 제공.
7. 결제가 지원되면 결제 금액을 확인한 뒤 발권 단계 진행. 미지원이면 공식 결제 화면 안내.

예약 성공, 결제 완료, 발권 완료는 각각 구분한다. 예약 응답이 불명확하거나 타임아웃이 발생하면 내역을 먼저 확인하고 중복 예약을 막는다. 예약번호 등 식별 정보는 필요한 범위에서만 보관한다. 로그인·결제 정보는 프롬프트나 일반 로그에 넣지 않는다.

## 도구 인터페이스 제안

아래 이름은 구현용 제안이며 실제 제공 API 이름이 아니다.

| 도구 | 역할 | 상태 |
| --- | --- | --- |
| search_trains | 운행시간표 조회 | MVP |
| get_booking_entry | 공식 예매 진입 링크 안내 | MVP |
| check_seats | 현재 잔여 좌석 조회 | 조건부 |
| reserve_train | 선택 열차 예약 | 조건부 |
| get_reservation | 예약 상태와 결제 기한 확인 | 조건부 |
| cancel_reservation | 취소 조건 확인 후 취소 | 후속 확장 |

이 프로젝트에는 RAG나 Vector DB가 필요하지 않다. 운행·좌석·예약 정보는 API의 현재 응답을 사용한다.

## 에이전트 지침 초안

> 사용자의 날짜·구간·시간 조건에 맞는 열차를 실제 조회 결과로 안내한다. 운행시간표와 잔여 좌석을 구분하며 조회하지 않은 좌석 상태를 추정하지 않는다. 예약 도구가 없으면 공식 예매 화면으로 연결한다. 도구가 지원되면 선택 조건과 금액을 확인한 뒤 예약하고, 실제 예약 내역을 검증하여 상태를 알린다. 결제·발권 완료는 확인된 경우에만 안내한다.

## 구축 체크리스트

- [ ] TAGO 활용 신청 및 서울·대전·신탄진 역 코드 확인
- [ ] 각 방향의 실제 응답·열차 종류·운임 제공 범위 확인
- [ ] 공식 사이트와 비교하여 날짜·시간·직통편 검증
- [ ] 공식 예약 API·제휴 가능 여부 및 이용 조건 문의
- [ ] 직접 예약 불가 시 공식 화면 연결로 완료 가능하게 구현
- [ ] 예약 지원 시 중복 요청·매진·타임아웃·결제 기한 처리 검증
