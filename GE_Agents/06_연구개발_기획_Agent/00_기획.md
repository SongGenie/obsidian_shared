## 목표와 현재 단계

기존 연구성과와 보유 기술을 이해하고, 신기술·정부 정책·지원사업의 변화를 근거로 후속 연구개발을 제안한다. 연결 순서는 **보유 자산 → 해결할 문제 → 추가 연구 → 지원 기회**다. 정책 키워드만 덧붙인 제안은 지양한다.

현재는 사용자가 제공한 대화 내용을 분석한 기획 단계다. 첫 구축 범위는 공고 통합 모니터링이며, 수집기·GE 연동·정기 실행·알림은 아직 구현하거나 검증하지 않았다. 제공 자료에 등장하는 정책 의결일, 사이트 기능, API·RSS 제공 여부는 이번 문서화에서 사실 확인하지 않았으므로 운영 전 원문 검증이 필요하다.

## 단계별 범위

| 단계 | 할 일 | 결과물 |
| --- | --- | --- |
| 1. 공고 모니터링 | 여러 출처 수집, 중복 통합, 변경 감지, 관련성·신청조건 분리 | 근거가 있는 통합 공고 목록 |
| 2. 연구자산 연결 | 대표 연구 3개의 실제 구현·검증 수준과 미해결 문제 정리 | 연구자산 카드와 공고 연결 근거 |
| 3. 후속 R&D 제안 | 신기술·정책 변화와 자산 연결, 선행연구·실현 가능성 검토 | 주간 후보 최대 3건, 선택한 1건의 상세 기획 |

1단계는 연구자료와 회사 정보가 부족해도 시작할 수 있다. 다만 회사 관련성과 신청 자격을 확정해서는 안 된다. 전국 모든 공고의 수집을 보장하지 않고, 수집처 목록과 실패 기록을 통해 범위를 확장한다.

## 역할과 처리 흐름

하나의 워크플로에서 역할과 입출력을 나누는 것으로 시작한다. 독립된 여러 에이전트 구축은 필수 조건이 아니다.

| 역할 | 입력과 판단 | 출력 |
| --- | --- | --- |
| 연구자산 분석 | 내부 보고서·제안서·실험 자료, 구현과 계획 구분 | 역량·한계·재사용 자산 |
| 신기술 조사 | 논문·공식 문서, 새로 가능해진 것과 제약 확인 | 기술 변화와 연구 기회 |
| 정책·사업 조사 | 정책 방향·수요조사·공고·RFP 구분 | 정책 흐름과 신청 기회 |
| 연구기획 | 자산·현장 문제·외부 변화 연결 | 후속 연구 후보 |
| 검토·평가 | 근거·중복성·차별성·수행 조건 확인 | 우선순위와 보완사항 |

흐름: 내부 검색 + 외부 수집 → 후보 생성 → 근거 검토 → 평가·저장 → 사람의 채택 판단.

신기술 조사에서는 “이 기술로 예전에는 어려웠던 무엇이 가능해졌는가?”에 답한다. 기존 [[GE_Agents/02_신기술_자료_정리/00_기획]]의 자료를 활용하되, 일반 기술 브리핑과 연구개발 제안을 구분한다.

## 연구자산 카드

프로젝트마다 다음을 기록하고, 근거가 없으면 미확인으로 둔다.

| 항목 | 내용 |
| --- | --- |
| 프로젝트·목적 | 누구의 어떤 문제를 해결했는지 |
| 보유 기술 | 직접 구현한 기능·알고리즘·소프트웨어 |
| 개발 상태 | 기획 / 개발 중 / 시제품 / 검증 완료 |
| 검증 근거 | 실험 결과·사용자 평가·시연 기록 |
| 재사용 자산 | 코드·데이터·콘텐츠·장비·협력기관 |
| 미해결 문제 | 성능·사용성·적용 환경의 한계 |
| 수행 조건 | 인력·기간·예산·외부 협력 필요성 |
| 출처 | 원본 문서·페이지·작성일·접근 권한 |

XR 웹툰 뷰어, AR 재활, EmoAI–Glass는 제공 자료에 등장한 **자산 정리 후보**다. 실제 보유·구현·검증 여부를 확인한 자산 목록은 아니다. 제안서에만 있는 기술을 구현 완료 역량으로 사용하지 않는다.

## 연구기획 카드와 평가

제안마다 제안명, 왜 지금인가, 활용할 기존 자산, 추가 연구내용, 선행연구·제품 대비 차별성, 검증 방법, 인력·기간·예산·협력 조건, 지원사업 연계, 내부·외부 출처를 남긴다. 검증 방법에는 비교 대상과 측정 지표를 명시하고 목표 수치의 근거가 없으면 가설로 표시한다.

지원사업 연계는 `확인된 공고 / 정책상 연관 / 추가 확인 필요`로 구분한다. 정책 방향 문서 자체를 신청 가능한 공고로 취급하지 않는다.

| 평가 기준 | 배점 |
| --- | --- |
| 기존 연구자산 활용도 | 25 |
| 현장 문제·수요 명확성 | 20 |
| 기술적 차별성·연구 필요성 | 20 |
| 인력·예산·기간 내 수행 가능성 | 20 |
| 정책·지원사업 적합성 | 15 |

각 항목에 점수와 근거를 함께 기록한다. 핵심 근거가 부족하면 총점 순위에서 제외하고 `추가 조사 필요`로 분리한다. 점수는 내부 검토 우선순위이며 선정 가능성을 의미하지 않는다. 제안 상태는 `검토 중 / 채택 / 보류 / 제외`와 판단 이유로 관리한다.

## 구축 방식과 제약

- GE는 확보한 자료의 검색·분류·요약·기획을 담당하고, 수집 프로그램은 원문 확보·변경 이력·실행 상태를 담당하는 구조를 후보로 둔다.
- 정기 수집은 승인된 기존 실행 환경 또는 앱 구독 내 기능으로 가능한지 검증한다. 불가능하면 수동 수집·파일 입력 POC부터 시작한다.
- 저장은 초기 POC에서 이 프로젝트 하위 로컬 자료를 사용할 수 있다. 로컬 파일 저장이 GE의 자동 검색·동기화를 뜻하지는 않는다. 업로드·검색 가능 여부를 별도로 확인한다.
- Google Drive·Gmail·Cloud Run·GCP 스케줄러 등 GWS/GCP 의존 경로와 추가 비용 서비스는 제외한다. 별도 API 사용권·호출 비용·인증 조건도 확인한다.
- 별도 벡터DB는 초기 필수 조건이 아니다. 마감·자격·지역·예산은 구조화 필드와 원문으로 확인한다.
- 정기 실행과 외부 알림 전송의 권한·승인 조건은 분리해 검증한다. 알림 채널은 미정이다.
