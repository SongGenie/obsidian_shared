## 목표와 현재 단계

외국어 원문을 한국어로 번역하고, 윤문·원문 대조 감수·최종 교정을 거쳐 의미 정확성과 한국어 가독성을 함께 확보한다. 사용자가 기존 경로에서 POC까지 진행한 이력이 있음을 공유하여 현재 단계는 POC로 기록한다. 실제 시험별 결과는 별도 증빙이 없어 확정하지 않는다.

## 사용 방식과 범위

- 사용자가 원문을 입력하면 요청 시 순차 실행한다.
- 기본 목표 언어는 한국어이며, 원문 언어는 입력 컨텍스트로 전달한다.
- 원문 의미·수치·단위·날짜·고유명사·문단 구조를 보존한다.
- 용어집과 스타일 가이드를 공통 적용한다.
- 최종 번역문과 품질 검토를 제공하고, 단계별 출력은 사용자가 요청할 때 제공한다.
- 파일 자동 수집, 정기 실행, 외부 서비스 전송은 제공된 설계에 포함되어 있지 않다.

## 에이전트 구성

| 에이전트 | 역할 | Knowledge |
| --- | --- | --- |
| 하루재 Orchestrator | 직접 번역하지 않고 순서·데이터·재작업·출력 관리 | 용어집, 스타일 가이드 |
| Translation Agent | 의미 보존과 정확성을 우선한 초벌 번역 | 용어집 |
| Korean Editing Agent | 의미를 유지하며 번역투와 문장 구조 개선 | 용어집, 스타일 가이드 |
| Translation Reviewer | 원문과 윤문본 대조, 오류 등급과 PASS/REVISE 판정 | 용어집, 스타일 가이드 |
| Korean Proofreader | 맞춤법·띄어쓰기·문장부호·표기 통일 | 스타일 가이드 |

## 처리 흐름

1. Orchestrator가 원문과 공통 컨텍스트를 전달한다.
2. 번역 → 윤문 → 원문 대조 감수를 순서대로 수행한다.
3. PASS이면 최종 교정을 진행한다.
4. REVISE이면 정확성 오류는 번역부터, 표현·문체 문제만 있으면 윤문부터 재작업하고 다시 감수한다.
5. 재작업 후 재감수는 최대 3회로 제한한다. 이후에도 REVISE이면 교정 후 미해결 이슈를 사용자에게 보고한다.

Critical 또는 Major 오류, 정보 누락·추가, 의미 불확실이 있으면 REVISE이며 Minor만 있으면 PASS할 수 있다. 교정 단계에서 의미 문제가 발견되면 직접 재번역하지 않고 감수 재확인 필요로 기록한다.

## 데이터와 출력

공통 필드는 `source_language`, `target_language`, `source_text`, `translated_text`, `edited_text`, `proofread_text`, `glossary`, `style_guide`, `review`다. 감수에는 상태, 재작업 대상, 재검토 횟수와 Critical/Major/Minor 목록을 둔다.

기본 출력은 `[최종 번역문]`과 `[품질 검토]` 두 섹션이다. 품질 검토에는 감수 상태, Critical/Major 오류, 용어·의미 확인 사항과 미해결 이슈를 표시한다.

## 공통 지식

- 용어집: 인공지능, 머신러닝, 대규모 언어 모델, 파인튜닝 등 표준 번역어를 적용한다. 하루재 도메인 용어 영역은 예시 수준이므로 실제 용어 추가가 필요하다.
- 스타일: 기본 합니다체, 명확하고 간결한 문장, 공식 제품명 유지, 숫자·SI 단위 공백과 퍼센트 등 예외 규칙을 적용한다.

## 구축 방식과 제약

기존 README는 Gemini Enterprise 앱의 Agent Designer에서 메인 1개와 하위 4개를 구성하고 Knowledge 파일을 첨부하는 방식을 제시한다. 이는 기존 자료의 설계 설명이며, 현재 계정의 기능 제공 범위·게시 여부·과금 적합성을 이번 문서화 작업에서 확인한 것은 아니다. 별도 GWS/GCP 리소스와 추가 비용을 도입하지 않는 공통 제약을 적용한다.
