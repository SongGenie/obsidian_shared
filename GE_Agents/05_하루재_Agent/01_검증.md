## 자료 정합성에서 남은 사항

- 에이전트 출력 지침은 대괄호 섹션을 쓰는 텍스트 형식이고 공통 스키마는 JSON이다. 텍스트를 구조화 필드로 변환·전달하는 방식과 스키마 검증 강제 여부가 명시되어 있지 않다.
- JSON 스키마는 상태·재작업 대상·횟수를 정의하지만 조건 간 일관성은 강제하지 않는다. `revision_count` 증가 및 상한은 Orchestrator 지침에 의존한다. `default` 선언만으로 실제 값 주입을 보장한다고 볼 수 없다.
- 불확실 표현, 번역 주의사항, 윤문 검토 필요, 교정의 감수 재확인 필요 항목은 공통 스키마에 전용 필드가 없다. 최종 품질 검토까지 보존하는 전달 규칙을 구체화해야 한다.
- 3회 재감수 후에도 오류가 남으면 교정을 거쳐 출력한다. 이때 교정 완료가 감수 통과로 표시되지 않도록 REVISE와 미해결 오류를 유지해야 한다.
- README 도식은 PASS 후 교정 경로를 중심으로 표현한다. 재검토 상한 도달 후에도 교정한다는 상세 규칙은 Orchestrator·routing_rules에 있으므로 함께 참조해야 한다.
- 테스트 1은 첫 등장 영문 병기를 필수 체크로 표현하지만 스타일 가이드는 병기 가능으로 서술한다. 통과 기준을 통일할 필요가 있다.
