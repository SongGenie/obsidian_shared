# 주간 보고 자동화 검증

대상 문서: [[GE_Agents/01_주간_보고_자동화/00_기획]]  
상위 문서: [[GE_Agents/00_GE_Agent_프로젝트_목록]]

## 검증 범위와 결론

실제 환경에서 수행한 POC 결과는 [[GE_Agents/01_주간_보고_자동화/02_POC]]에 별도로 기록한다.

**결론: 제한 조건을 반영하면 구현 가능하지만, Gemini Enterprise Workflow Builder만으로 다른 사람에게 무인 정기 메일을 보내는 설계는 현재 문서상 성립하지 않는다.** 예약 실행은 지원되고 Gmail의 `Send message` 액션도 제공되지만, 예약 실행에서 자신 이외의 사람에게 이메일을 보내는 경우 사람의 승인(HITL)이 필요하다. 무인 발송이 필수라면 승인 지점을 유지하거나, 승인 요구사항을 충족하는 별도 발송 경로를 설계·검증해야 한다. [Workflow 일정·제약](https://docs.cloud.google.com/gemini/enterprise/docs/workflow-builder/quotas-and-limits), [커넥터 액션](https://docs.cloud.google.com/gemini/enterprise/docs/workflow-builder/use-connector-actions)

## 구현 전 결정이 필요한 사항

- 실제 대상 채널, 공개/비공개 여부, 사용자/봇 주체와 승인된 Slack 범위.
- Slack 수집 경로: GE 커넥터 검색형 POC 또는 범위·페이지 처리·속도 제한을 구현하는 Slack API 수집기.
- GE 에디션, 앱 리전, Workflow Builder 기능 토글과 예약 실행 지원 여부.
- 발송자, 수신자, 메일 커넥터, 타인 발송 승인 허용 여부. 무인 발송이 필수라면 대체 발송 경로.
- 실행 주차 키 저장소, 스레드 재확인 상태, 재시도 및 중복 억제 방식.
- 수정/삭제 메시지, 탈퇴 사용자, 접근 불가 채널, 부분 실패 시 보고서 표기 방식.

## 권장 검증 순서와 통과 기준

1. **환경 확인:** GE 앱 에디션·리전·Workflow Builder 토글·Slack/Gmail 연결 및 계정 인증을 확인한다. 예약 자격 증명 갱신 주기를 운영 담당자에게 할당한다.
2. **Slack 표본 수집:** 한 채널의 한 주 메시지를 API 원본과 비교한다. 주 경계, 페이지네이션, 답글, 과거 스레드의 주중 답글, 비공개 채널 접근 여부를 각각 기록한다. 누락된 페이지 또는 접근 범위가 설명되지 않으면 통과시키지 않는다.
3. **근거 링크·요약 비교:** 각 보고 항목이 실제 메시지/답글에 연결되는지 확인하고, 샘플 한 주를 사람이 작성한 보고서와 비교해 사실 오류·누락·추론을 기록한다.
4. **발송 흐름:** 테스트 수신자로 초안을 검토하고, 자기 자신과 다른 수신자 각각의 승인 요구를 확인한다. 승인된 메일만 성공으로 기록한다.
5. **실패·중복 시험:** 페이지 조회 실패, 스레드 조회 실패, 자격 증명 만료, 예약 실행 재시도, 발송 실패 후 재실행을 발생시켜 주차 중복 발송이 없고 수집 실패가 보고서에 표시되는지 확인한다.

**POC 통과 조건:** 기간 경계와 메시지/답글 표본이 원본과 일치하고, 모든 요약 항목이 실제 permalink로 추적되며, 수집 실패 범위가 드러나고, 재실행으로 동일 주차 메일이 중복 발송되지 않아야 한다. 타 수신자 메일은 실제 설정에서 요구되는 승인을 충족해야 한다.
